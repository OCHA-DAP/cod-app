## Purpose

This standard operating procedure defines how COD-AB (Common Operational Dataset, Administrative Boundaries) datasets are produced, updated and published, from update request to closeout. All Data Quint members follow this one joint process, so the humanitarian sector works from commonly agreed, harmonized boundaries, with less duplication and consistent geocoding.

## Principles

- **Two tracks.** Where OCHA has a presence, OCHA HQ and the <Term term="imwg">IMWG</Term> (coordinated by OCHA) run the update. Where it does not, the <Term term="cod-ab-wg">COD-AB Working Group</Term> (WG), defined in a separate TOR, agrees a Lead Agency from its member agencies, and that agency runs the update through its HQ and country team. In both tracks, the WG reviews the Candidate in Step 5.
- **Update cycle.** The process applies after release of the baseline v1 dataset. Each Member Agency HQ keeps a full list of its country teams and sends them the form for each release. The agency whose country team responds conducts the next update. If it cannot provide data or capacity before the review period ends, the WG looks for an alternative.
- **Emergency fast-track.** In an emergency, the WG can agree a fast-track at one of its meetings, and decides there which steps to simplify or skip. Each step then takes 1 day, though it can take longer depending on the situation.
- **Shared mailboxes.** Each Member Agency HQ keeps a shared mailbox (for example cod@agency.org) for all COD-AB correspondence, so work continues when staff rotate.
- **Admin 0 reference.** By default, every dataset is <Term term="edge-matching">edge-matched</Term> to a global admin level 0 reference agreed by the WG, so admin 0 and all subnational levels fit together worldwide. OCHA HQ proposes minor adjustments (for example more precise coastlines from several sources), and the WG approves them. Disputed territories and areas are stored as separate entities, following the agreed admin level 0 master list, and can be merged as needed at extraction.
- **Tools.** No step depends on a specific tool. Each one can be done with the shared workspace, a ticketing system (Jira) and standard GIS software. Where optional tools exist, the review request email links to them.
